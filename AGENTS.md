# AGENTS.md

Source for **bedrockvoicechat.com** — the marketing site and the wiki, one Astro project.

## Layout

| Path | What |
|---|---|
| `src/pages/index.astro` | Marketing page. Owns `/`. |
| `src/content/docs/wiki/**` | The wiki. Starlight owns `/wiki/**`. |
| `src/styles/tokens.css` | **The only file allowed to contain a hex value.** |
| `src/lib/site.ts` | Facts — versions, URLs, feature gates. Not design decisions. |
| `src/data/version-matrix.json` | Generated. See below. |
| `scripts/` | Build-time generators and checks. |

Nesting docs under `wiki/` is what puts them on `/wiki/**`; Starlight 0.41 removed `routeBasePath`. The marketing page keeps `/` because a static route outranks an injected dynamic one.

## Commands

```
npm run build     # gen:versions -> astro build -> check:links
npm run check     # astro check
npm run dev       # local, --host
```

`build` fails on a broken internal link. That is deliberate — Starlight does not validate links, so nothing else catches a renamed page.

## Rules

**Never hand-edit the tables in `platforms/version-support.md`.** Everything between the `<!-- generated:version-table -->` markers is rewritten by `scripts/version-support.mjs` on every build. Edit the prose around them freely.

**`version-matrix.json` comes from another repo.** Regenerate when the `bedrock-protocol` pin moves:

```
cd ../bedrock-protocol-rs/bedrock-protocol
cargo run --example version-matrix > ../../bvc-pages-src/src/data/version-matrix.json
```

**Adding a page** means creating the file. The sidebar autogenerates from the directory tree; order comes from `sidebar.order` in frontmatter.

**Renaming or removing a page** means adding a redirect in `astro.config.mjs`. Old URLs are linked from Discord and indexed.

**Screenshots** are `<div class="shot"><span>caption</span></div>` placeholders. They render as a dashed box, deliberately visible. Replace with an `<img>` and delete the div.

**Say "Addon", not "behavior pack".** The Bedrock artifact is a behavior pack plus a resource pack; Addon is the term for both.

**Asides** are Starlight syntax — `:::note`, `:::tip`, `:::caution`, `:::danger`, optionally `:::tip[Custom title]`. Three colons, not two.

## Tone

Match the surrounding pages. Concretely: descriptive headings, no cheerleading, no rule-of-three cadence, no editorial narration of the document ("worth noting", "the short version"). State the fact, then the mechanism. Bold sparingly — precision carries the emphasis.

## Verifying content

Documentation claims are checked against the BVC source, not written from memory. Two failures got through by being plausible: `/api/liveness` (only mounts at `/health/*`) and the Java mod's embedded ports (8444/8443, not 443).

Before documenting a config key, default, endpoint, or command, read it in the source. For the HTTP API, generate the spec rather than grepping route macros:

```
cd ../bvc/server/server && cargo run --example openapi_spec --features bedrock
```

## Machine-readable output

Every wiki page is also served as raw markdown at the same URL with `.md` appended, plus `/llms.txt` (index) and `/llms-full.txt` (whole corpus). Generated by `src/pages/wiki/[...slug].md.ts` and the two `llms*.txt.ts` endpoints; each page advertises its twin with `<link rel="alternate" type="text/markdown">` via the `Head` override.

## Deploying

Push to `gh-pages-src`. The workflow builds and publishes to the root of `gh-pages` with `keep_files: true`.

`gh-pages` is shared with five other publishers — `/api`, `/websocket`, `/updater`, `/builds.json`, `/discord`, `/.well-known`. A publish with `keep_files: false` would delete them, and removing `/updater/*.json` silently breaks auto-update for every installed client. The workflow has a guard that fails on unrecognised root paths; add to `KNOWN` if a legitimate new one appears.
