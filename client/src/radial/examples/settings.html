Radial · settings

A second screen, not a second app

Settings is presented over the dashboard rather than instead of it. The dashboard behind is holding a voice link, a roster and a position feed; replacing it to show a checkbox means rebuilding all of that on the way back. So it stays mounted, scaled back and visible at the top edge — which is also the only evidence a reader has that dismissing goes backwards.

Presentation

Rises, covers, dismisses

The whole shell travels as one surface, rail included: the rail's gear is lit while settings is up, so the rail belongs to this screen for as long as it is here. The gap at the top is load-bearing rather than decorative — full-bleed, a cover is indistinguishable from a navigation, and nothing about it suggests that Escape or the back gesture will return you to what you were doing.

Dismissal follows the platform, not the component. On a phone the first back climbs from a pane to the section list, and the second closes; the back control says which by being an arrow or an ×. On desktop the section list is never hidden, so there is nothing to climb and Escape closes. A menu or a modal open on top always takes Escape first.

Panes

Nine surfaces, one kit

Rows, toggles, selects, one dropdown that serves both selects and row actions, tables, chips, callouts, empty states and a confirm. Every pane is built from those, on real content rather than lorem, so the kit gets tested against the awkward cases: a device list that comes from two audio hosts, a backend that is chosen by recognition, a capability the server may or may not have told us about.

Proxy and Realms are the server-select screen wearing a different hat. Both are asking the same question — which place should this point at — so both use its plate, with favourites and the operator's own entries folded in. The warning that you must join 127.0.0.1 rather than the server itself is the most support-generating fact in the product, so it is a callout on both of them and not a footnote on either.

Mobile build and phone width are different switches, deliberately. A narrow window on a desktop is still a desktop: it records, it picks its own audio device, it has more than one network interface to bind to. Driving capability off the container width is how a resized window loses features it still has.
