Which of your servers, and will voice actually work on it

The screen between sign-in and the dashboard. A plate per server, where the glyph at size is the recognition object and the name only confirms it. The ring is deliberately absent: it is the empty state and the status oscilloscope, never a roster, because picking a server wants recognition rather than recall.

The screen

Plates, and a preflight behind each one

Every plate carries the same five things: identity, name, host, state, and a preflight strip of four blocks and a total. The blocks are the cheapest honest summary — you can see that something failed and roughly how far in without opening anything. Every breakpoint is @container rad, so the phone toggle is genuinely just a width change.

Preflight

Four checks, in the order that already runs

Three of these are what ServerHealthService.check does today, in its order; the panel names them and times them rather than collapsing them into one badge. The verdict is first-failing-check-wins, matching Diagnostics.verdict — somebody reading this has a problem, and a wall of green with one red line in the middle makes them do the diagnosis themselves.

the sequence A failed check skips the rest, and the skipped ones say so rather than sitting at pending forever. 
1 Credentials  get_credentials + is_certificate_expired
2 Handshake    api_initialize_client + api_get_config
3 Protocol     config.compatible / client_too_old
4 QUIC path    UDP probe to the advertised QUIC port   // ← the new one
certificate expiry is checked, never shown It is the mechanism, not the message.

is_certificate_expired is the reason a server asks for a fresh sign-in, so it stays in check one — but it is folded into Credentials and never named. Days-until-expiry, the issuing CA and the rotation window are all facts about mTLS, and a player who sees them has been handed a transport detail to interpret when the only thing they can act on is sign in again. The readout says signed in as Petra, or it says you are not.

why the fourth check earns its place The failure it catches is invisible to the other three.

Every check above it runs over TCP 443. A network that permits HTTPS and drops UDP passes all three, and then the connection cannot carry a single audio frame — which surfaces later as a bare QUIC01. Probing the UDP path here turns the most confusing failure the product has into a sentence on the screen you were already looking at, before you committed to the server.

Voice blocked is a hard blocker, not a warning. Voice is the product, so there is nothing worth connecting to without a UDP path, and the connection would fail anyway. The plate offers Recheck and nothing else — a “connect anyway” button here would only sell a failure as a choice.

States

Four that exist, one that is new

The first four are what ServerCardManager.deriveBadge and deriveButton already produce, renamed only where the current wording is vague. Nothing here invents a state the client cannot currently be in, except the last.

Status Chip Primary action Where it comes from
checking Checking… none, disabled initial state, and during a recheck
connect Ready · Ready · slow Connect compatible, signed in, UDP open
reauth Sign in needed Sign in no saved sign-in, or it has expired
version_mismatch Update needed blocked, names both versions client_too_old either way
udp_blocked Voice blocked Recheck — never connect new — the fourth preflight check

Identity

Operator art on top of the derived glyph, never instead of it

ServerCardManager.loadImages already fetches {server}/assets/avatar.png and {server}/assets/canvas.png on a seven-day cache, and either can be absent. So the glyph is the floor and the art is the override: avatar.png takes the identity tile when it exists, and canvas.png fills the head of the plate, veiled into the violet ground before it reaches any text.

all three asset cases Real plate heads, not an illustration of one. The art here is generated from each server's own hue — the reference pages reach nothing over the network. In the client these are real fetches that can fail.

Routing

This page has no empty state

Server.initialize resolves the list before revealing anything, and two of the four cases never reach this screen at all. Designing an empty state for it would be designing for a case the router already handles — so the “1, unhealthy” scenario above is the smallest list this page can honestly render.

0 servers Redirect to /login. Never seen.
1, healthy Preflight passes, redirect straight to /dashboard. Never seen — the preloader stays up so the list cannot flash.
1, unhealthy This page, one plate. Only version_mismatch stops here today; a failing UDP probe would join it.
2 or more This page. Every server preflights in parallel, and the plates resolve as their own checks land.
